# 👤 User Personas

These are task-oriented personas for design and documentation. They are not real users and do not imply analytics or collected profile data.

## Persona A: C learner
**Goal:** Understand how a terminal loop, string matching, functions, and enums work.

**Needs:** A small source file, easy compile commands, deterministic examples, and explanations of rule order.

**Potential friction:** Confusing this rule matcher with an AI chatbot, or assuming the checked-in executable is current for every platform.

## Persona B: First-time contributor
**Goal:** Make a focused change and verify it before opening a pull request.

**Needs:** Project setup, test commands, expected behavior, code conventions, and a clear issue template.

**Potential friction:** Missing a boundary case such as EOF, a long line, or “bye” as part of another phrase.

## Persona C: Maintainer
**Goal:** Keep the program small, safe, testable, and accurately documented.

**Needs:** Reproducible tests, architecture decisions, supported behavior, and private security disclosure instructions.

These personas should be revised only when the project gains genuinely different user groups or capabilities.
